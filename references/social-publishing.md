# 社交媒体：分期与打包建议

仅在用户要求社交媒体素材时增加发布层；沿用原技能“以知识单元组织、每卡完成实质子问题、张数由内容决定”的原则。任何示例标题、叙事顺序或张数都不是固定模板。定义、原因、例子和边界可以放在同一张卡；仅当容量、可读性或独立子问题需要时分卡，不为“引入 / 解释 / 边界”各造一张。

完整机制可以分为讲解篇与自测解答篇，小知识点可以合成一期；是否拆期按读者能否完整理解和独立作答决定，不按卡片类型机械拆期。练习篇给足题目条件，先题后答；题答保持独立 PNG，每道题有完整解答。素材分期不改变母版中的知识覆盖与同源 solution，不自动发送或发布。

## 存储

母版严格沿用 output-storage.md：批次根目录保留 manifest、三类 PNG、文字稿、来源和校验报告，不新增 master 层或搬动原产物。需要发布包时，仅在同一批次下新增 posts/，一期对应一个子文件夹。

每期 PNG 直接按上传顺序平铺，命名为 01-具体标题.png 等；不必再建 images/ 层。配文需要保存时增加 post.md。批次级发布映射记录“期次 / 发布文件 / 母版 card_id”，只有重导或自动化需要时维护，不强制每期增加独立 mapping.json、哈希清单或空文件。发布包从母版导出，内容修订回到母版处理，避免复制另一份独立答案数据。

page 表示一组连续内容的页次，不默认等于整期上传序号。文件名控制上传顺序；图片页码仍沿用单张留空、多张显示 index/total 的规则。若要改为整期 N/M，须显式定义发布版分页并重新渲染。

需要交付时可按期压缩，整套总包按需求另加；不为每次制卡默认生成重复压缩包。

## 整理与验收

1. 从已核对的知识单元确定本期任务和图片顺序。只有影响交付的平台限制未知时才询问，不将示例标题、封面或固定张数设为必备项。
2. 从已通过校验的母版选取 PNG，复制到 `posts/期号-具体主题/`，按上传顺序编号。同一期中的问题必须能独立作答，并包含引用的全部解答页；必要前提与结论保持可定位。
3. 需要配文时写 `post.md`，包含帖子标题、正文和必要来源或版本条件；只使用已核验内容。已有帖子素材重导时保留用户修改的文案与其他文件，不覆盖未确认的同名内容，也不静默混留失效图片。
4. 核对导出顺序、题答覆盖和 PNG 与当前母版一致性；有修改则重渲染母版再导出。交付实际期数、每期目录和可选压缩包，说明只完成本地素材。

本规则由 agent 在母版渲染后执行；现有渲染器仍只导出三类母版 PNG 和同源配套文件，不宣称它会自动生成 posts/。
