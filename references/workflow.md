# 口述核对、讲解带练与复习

## 先确定要检验的能力

分开读取用户的目标和当前解释。自由口述先抽取有意义的主张；看题作答则使用该题 `solution.criteria`、`critical_errors` 和 `accepted_variants`。若已有自述足够定位问题，直接核对，不重复要求解释一遍。

把范围内的必要定义、机制、前提、例子、边界和显式追问对应到知识单元、讲解卡与自查题。内容完成时，各项有准确解释及依据；是否掌握由真实回答另外决定。对纯事实、不同学科和有争议的问题使用适合的证据标准，不硬造因果或唯一立场。

## 按含义核对口述

输入来自当前对话支持的语音、平台转写或用户提供的文字。只看到转写时，不判断发音和口语流畅度；疑似术语或否定词转写错误，针对该处待确认，同时保留其他确定的判断。

先保留能定位原意的短引文，再作以下区分：

| 判定 | 使用情形 | 下一步 |
|---|---|---|
| 正确 | 当前主张的对象、关系与条件成立 | 简要确认，继续检查题目要求 |
| 部分正确 | 大方向对，缺少必要限定或关键步骤 | 指出缺失处及其对结论的影响 |
| 错误 | 对象、因果、计算、关系或结论有误 | 指出原述错在哪里，提供准确解释 |
| 尚未覆盖 | 必需点尚未说到 | 记录遗漏，与已经说错分开 |
| 待确认 | 指代、表达或转写歧义影响判断 | 仅确认该处，不替用户补成正确回答 |

按题目目标检查概念、机制、条件与应用中适用的维度。必需语义点都覆盖且无关键矛盾才通过；可选拓展不影响通过。合理改述、不同解释顺序、短句、图或箭头均可接受。核心错误不能用其他答对项抵消；关键词齐全也不能掩盖因果讲反。

`accepted_variants` 是已经确认的合理示例，不是穷举白名单。遇到未列出的有效说法，依据知识基线判断；发现 solution 本身有错时先核实修订同源答案及相关卡片，再评价用户，不能以维护参考答案为由否定正确解释。

多个错误可以简短列全，再优先修补最阻塞理解的一项，保留其余问题。反馈顺序可采用：本次判断 → 已讲对部分 → 缺口与依据 → 必要补讲 → 一个变式复检任务。依据应足够具体，让用户知道怎样修改解释；不需要每次填一份形式化评分表。

### 判定示例

题目背景：InnoDB 表以 id 为主键，age 有普通二级索引，name 不在该索引中。题目要求说明按 age 查询 name 的常规查找路径，暂不讨论覆盖查询的可见性细节。

- “先在 age 索引找到 id，再拿 id 去主键索引取 name。”关系正确；“主键索引”是此背景下对聚簇索引的合理说法，不因未说术语而扣分。
- “先找到 id 再取 name，因为二级索引叶子保存整行。”路径结论正确但理由错误，整体尚未通过；解释二级索引记录与聚簇记录的区别。
- “二级索引肯定都要回表。”过度概括，需说明所需列是否已在索引中等条件；不能只因本题恰需取 name 就接受该一般主张。
- “先用 age 找 id。”这个步骤正确，取得 name 的部分尚未覆盖，不将已说步骤判错。
- “叶子里面放主见。”可能是“主键”的转写歧义，保留待确认，不能据此判定概念错误。

实际使用该示例时仍应核查适用版本；知识依据可参见 [MySQL 8.4 聚簇与二级索引](https://dev.mysql.com/doc/refman/8.4/en/innodb-index-types.html)。

## 带练循环

有基础时先请用户自己解释；零基础或完全无从开口时，先提供可理解的讲解和完整例子。学习前说明稍后需要解释的目标，例如“读完后说明为什么选择这种结构”。

按缺口补学：概念混淆就给同条件对比，推理断裂就补关键中间步骤，不会应用就走一遍完整例题。讲解要有足够内容支撑结论；无需把每轮限制为固定字数。一个段落可以完成一条因果链，长解释可以用标题、步骤和图表分层。

补学后请用户脱离答案，换一个小情境重讲同一关系。刚展示答案后的复述记“有提示完成”；真正独立的新题表现才支持“当场独立通过”。单元末安排整体解释，把分开的知识重新串起来；一次回答已覆盖的能力无需重复考查。

交互时每次留下一个主要待答任务；用户要求直接看答案就直接给，并如实保留未独立检验状态。批量新增题目时配齐答案，不把新悬念混进复习材料。

### 提问选择

| 当前目标 | 可用问法 |
|---|---|
| 重建概念 | “向第一次接触它的人说明，它是什么、解决什么问题。” |
| 解释机制 | “为什么会得到这个结果？说明关键中间关系。” |
| 追踪过程 | “给定这些输入，沿步骤说明数据怎样变化。” |
| 改变条件 | “若这个条件改变，原结论是否成立？依据是什么？” |
| 辨错与边界 | “这段解释哪里不准确？怎样改写才成立？” |
| 整体整合 | “把这些环节连起来，说明从输入到结果的过程。” |

题目按目标选用，不要求一轮集齐。明确区分“题目已给的事实”和“用户需要解释的关系”。新手需要支架时，先给完整例题再减少提示；熟悉之后在已学内容中混合少量相似题，练习方法选择。

## ADHD 友好的学习节奏

降低寻找重点和恢复任务的成本：说明当前问题，稳定导航，用适当标题与留白呈现阅读路径。允许口述、书写、图示或短句；根据个体反馈调整长度和节奏。

用户觉得信息多时，收拢到一个当前子问题，给完整的结论与必要依据，把剩余范围记下。减少当前任务量，不删掉使知识成立的前提和因果。暂停时留下目标、已检验点、当前缺口和恢复入口；回来从那里继续。

## 交付与快速复习

三组 PNG 分别用于理解、作答和核对。快速复习从 `self-check/` 进入，先回答，再打开同题 `answer/`，只回看缺口对应的 `explanation/`。`manifest.json` 与 `transcript.md` 含答案，不作为纯自查入口。

渲染器从 manifest 导出文字稿、来源与复习映射；真实作答记录由 Agent 单独保存在 `learning-log.md`（仅发生核对时需要）。记录目标/题号、回答摘要、缺口、提示情况、状态和下一步即可；不把通用答案里的常见错法写成用户个人错误。

| 学习状态 | 所需证据 |
|---|---|
| 未检验 | 没有可核对的实际回答；包括已经讲解但尚未答题 |
| 待修补 | 核心错误、必需点遗漏或无法作答 |
| 有提示完成 | 看过答案、用提示或步骤支架后完成 |
| 当场独立通过 | 约定闭卷条件下独立解释或应用成立 |
| 延迟通过 | 经过一段时间后实际无提示通过同一目标 |

回答正确但不确定是否闭卷时，写“作答正确，独立性未确认”，不追认独立通过。渲染成功、阅读材料、说“懂了”都不能替代回答证据。延迟通过也不代表永久掌握。

复习间隔按期限和实际表现调整：忘记时补学并较早复检，稳定独立答对再延长。次日或几天后仅是起点，不承诺精确预测遗忘；用户明确要求提醒时才使用可用提醒工具。

完整范围内尚未核验的事实和未通过的能力如实保留。前者阻塞对应内容完成，后者不阻塞已授权的正确卡片制作。用户暂停学习时可正常交付已完成材料，不无限追加必答题。
