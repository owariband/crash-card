# 内容设计与排版

## 用知识单元控制完整性

先为单元写一个可检验目标，例如“解释缩放点积注意力的计算顺序与缩放原因”。再决定讲解、自查与解答的张数。深入模式增加解释链与验证例子；连续卡各自回答一个完整子问题，并显示单元及页次。单元结束安排能串起关系的整体题。

内容的最小单位是一段成立的解释：对象明确，结论有依据，条件能定位。要点可以长短不同；有五个必要步骤就呈现五步，排不下则有意义地分卡。删掉一个句子前，检查读者是否仍能知道“为什么、在什么条件下、怎么得到结果”。

例如，“B+ 树查询快、适合范围”不足以作为讲解。应交代：在相同页大小和相近键宽等条件下，内部节点主要存键和子指针，可容纳较多分支，有机会降低树高；范围查询可定位下界后沿叶层有序扫描。缓存命中和具体查询仍影响开销，不能把树高直接等同于实际磁盘读取数。必要时把结构原因和范围路径分成两张。

## 六种主体版式

| 版式 | 组织内容 | 完整性要求 |
|---|---|---|
| 概念 `concept` | 准确定义 → 关键关系 → 正例或边界 | 定义说明对象与决定性特点，避免术语循环解释 |
| 公式 `formula` | 问题 → 公式 → 符号/维度 → 推理 → 算例 | 写明假设，关键推导不跳步；每张可只完成其中一个完整子问题 |
| 流程 `process` | 输入 → 步骤/分支 → 输出 | 标明箭头的顺序、数据流或因果含义；说明关键跳转为什么发生 |
| 对比 `comparison` | 相同维度逐项比较 → 差异的影响 | 对比条件一致，优势附成立条件；避免“快/慢”替代原因 |
| 例题 `worked_example` | 已知 → 操作及理由 → 结果 → 变化影响 | 有关键中间过程，结果与单位可核对；例子不替代一般结论 |
| 纠错 `misconception` | 已标明的错误说法 → 错因 → 准确表述 → 边界例子 | 让正确表述成为视觉重点；不要把错误说法无标签地放在标题 |

这是选型依据，不是固定章节。正文区块可以组合，卡片用途与版式独立；例如解答也能采用公式或流程版式。受支持的区块字段、数学与图形边界见 [card-schema.md](card-schema.md)。

## 自查与解答

自查题要求用户重建关系或应用知识。准确术语可以使用，但应能用普通语言解释其含义；不要求装作教儿童。题干可以分必要子步骤，但围绕同一主要目标。

选择与目标吻合的任务：解释“是什么/解决什么”、说明“为什么”、追踪“怎样发生”、判断“条件变了会怎样”、纠正“不准确在哪里”。题面只提供完成任务所需的事实与中性作答要求，详细核对点放在解答里。考定义时避免标题给出定义；考机制时可明示待解释的结论。

解答先给最短充分结论，再给关键理由或过程，附必要语义核对点和补学定位。三者可以合并为连贯段落，不机械套固定块数。题目要求几种情形，答案就处理几种；“其他类似”不能替代关键分支。较长答案连续多张，整组引用同一题的 solution，卡面标清页次。

## 1200×1600 排版与检查

新版画布固定 1200×1600 px，四周保留约 72 px 安全区域；标题、卡片类型和编号位置稳定，主体随内容变化。配色浅底深字，重点克制，标签同时说明颜色含义。

正文优先使用 46–52 px，重要图表文字原则上不小于 44 px；标题约 64–76 px。这些是初始设计参数，实际布局由渲染器测量。约 400 px 宽的预览能暴露手机阅读时过小的标签；渲染成功后仍须目视检查。

正文用段落、标题、步骤、表格或图示呈现关系。段落在意思转换处断开，因果和必要条件留在一起；可扫描性依靠层级与留白，而不是把句子一律切短。表格需要同列可比、完整行与清楚的行高；流程需明确方向与分支标签。

数学使用本地 mathtext 支持的公式子集与单独的矩阵区块；不是完整 LaTeX 引擎。公式中用数学符号，中文解释放相邻正文/表格；复杂表达不被支持时改成等价受支持表示或分步展开，核对含义不变。流程图支持有限分支的 DAG；循环和复杂网络另选步骤说明或拆图，不把模型不支持的图悄悄删减。

排不下时依次：删除冗余 → 改写含混长句 → 换表示 → 按完整子问题拆卡。保持条件、步骤与答案标准。静默截行、隐藏区块、压到不可读字号都不满足交付。
